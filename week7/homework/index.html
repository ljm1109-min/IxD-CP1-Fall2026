Rhythmic Blend Grid

About the Sketch

I started from the grid sketch we made in class and developed it into a rhythmic composition. Every cell has the same three shapes (a rectangle, a circle, and a triangle), but each shape changes a little depending on where its cell is. I used the column number (i) and row number (j) to shift size and color, a sine wave to make the shapes ripple across the grid diagonally, and the distance from the center of the canvas to make the circles largest in the middle and smaller toward the edges. The shapes overlap in SCREEN blend mode, so the colors mix where they meet.

Problems and Solutions

1. From random noise to rhythm

In the class version, the triangles used random() for their color and all three corners. Each cell looked completely different, so the triangles felt more like noise than rhythm. After reading the article on repetition, pattern, and rhythm, I understood that rhythm is repetition with variation that follows a rule.

I replaced the random triangles with rule-based changes. Their color now shifts step by step with i and j, their size grows from top to bottom, and they rotate with a sine wave. I kept only a very small random value (plus or minus 5 pixels) so the shapes still feel a little hand-made.

2. The grid lines disappeared in SCREEN mode

When I used blendMode(SCREEN), the grid lines from class were no longer visible. The default stroke color is black, and in SCREEN mode black does not change the colors underneath, so the lines simply vanished.

I changed the line color to a semi-transparent white with stroke(0, 0, 100, 40). I also used noStroke() before drawing the shapes, so only the grid lines have an outline and the shapes stay as soft blocks of color.

3. Flickering after adding movement

My first version drew the image only once. When I changed it to move, draw() started running about 60 times per second. Two problems appeared. First, random() gave new values every frame, so the triangles shook and flickered. Second, because the blend mode was still SCREEN when I painted the background, the background did not fully clear the previous frame.

For the flickering, I added randomSeed(0) at the start of draw(). This makes random() start from the same point every frame, so the small variations stay the same. For the background, I switch to BLEND mode, paint the background, and then switch back to SCREEN before drawing the shapes.

New Functions I Learned with an LLM

I worked through this sketch with Claude. These are the functions and values I used that we had not covered in class yet.

Function / value What it does in my sketch
dist() Measures how far each cell is from the center of the canvas (uses the Pythagorean theorem). I use it for the symmetry of the circles.
sin() Creates a smooth wave that goes up and down between -1 and 1. I use it for the rippling and rotating motion.
frameCount Counts the frames since the sketch started. Multiplying it by a small speed value makes the waves move over time.
randomSeed() Makes random() give the same values every frame, so the triangles do not flicker.
push(), pop(), translate(), rotate() Move the drawing point to the center of a cell and rotate only that triangle, without affecting the other shapes.
HALF_PI A built-in value for 90 degrees. rotate() uses radians, where 180 degrees is PI.
% Keeps the hue value inside 0 to 360, so the color goes around the color wheel again instead of going past red.
